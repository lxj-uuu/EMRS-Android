## 2. 问题清单

### P0（必须修）

**P0-1 RxFrameParser 收块时不对"整块找最后一个 A0A0"做重扫，偏离源码且自带单测必失败**
- 位置：`protocol/RxFrameParser.kt:44-75`（feed）
- 依据：LX1.PAS L407-415 —— 每次收到字节块，先 `for ij:=1 to count-1` 扫描**整块**中最后一个 `A0A0`，找到即 `msg_ii:=1; buf_ii:=ij+2` **丢弃既有累积**、从其后重新累积。该扫描无条件执行（不只在 !have_head 时）。
- 现实现：一旦 haveHead=true，后续字节全部进缓冲；缓冲中途出现 A0A0 不作帧头处理；跨块续帧时也永不重扫新块。
- 复现（cross_check.py 用例 A/B）：
  - 块 `A0 A0 07 07 A0 A0 01 01 AF AF`：Delphi 语义 → 合法帧 type=1；Kotlin 实现 → 校验恰好为 0 的假帧 type=7。**且仓库自带单测 `RxFrameParserTest.newHeaderResetsAccumulation` 断言 type=1，运行必失败**——说明该测试从未被执行过。
  - 跨块续帧、第二块数据内含 `A0A0`（约 4% 概率/帧，2900B 载荷）：Delphi 语义丢弃前缀、从 A0A0 后重扫（原版怪癖，可能产出校验恰为 0 的畸帧或 NAK）；Kotlin 实现正常解出 type=2。两语义结果不同。
- 修法建议：在 feed() 累积态中，检测"刚写入字节与前一字节均为 0xA0"即 `msgLen=0` 重启（等价块内重扫）；并在每次 feed() 开始时对整块做最后一次 A0A0 扫描，命中则丢弃既有累积（完全等价源码）。修后 `newHeaderResetsAccumulation` 应转绿；同时修正其 KDoc 中"逐字节等价实现"的失实表述。
